Gantt Chart Custom Widget

Implementation guide for SAP Analytics Cloud (SAC)

Prepared by Daya Paonam, AlphaOak · September 30, 2026 · Reference: SAP Community blog – Introducing the Gantt Chart Custom Widget for SAC

1. Overview

This guide describes how to build a Gantt chart in SAP Analytics Cloud using the UI5 Gantt Chart custom widget. The widget does not bind to a model directly. Instead, a standard SAC table reads the data, and a script passes the table's result set to the widget with setDataSet().

Excel file→SAC model→Table_Tasks→Script: getResultSet()→GanttChart_1.setDataSet()
Important: the widget only shows data when the story is run (View mode). It stays empty in Edit mode.

2. Prerequisites

  • A story using the Optimized Design Experience (classic stories don't support scripting). Convert an existing story with File → Convert to Optimized Design Experience.
  • Advanced Mode switched on in the story editor (toggle on the right of the top toolbar).
  • A SAC role that allows creating custom widgets, models and scripted stories.
  • The widget files UI5GanttChart.json and UI5GanttChart.zip, downloaded from the GitHub link in the SAP blog.

3. Data preparation

3.1 Source file structure

The source file is GanttChart_Sample_table_populated.xlsx. Each row is one bar. Segment rows are parents; task rows point to their segment through ParentID.

3.2 Scheduling assumptions

  • Working hours 08:00–16:00, Monday to Friday; weekends skipped.
  • Tasks run in sequence: each starts when the previous one ends.
  • Segment 1: Oct 5 – Oct 14, 2026. Segment 2: Oct 19 – Oct 28, 2026.
  • A segment row runs from its first task's start to its last task's end.
These dates are a sample schedule. Replace them with real planned dates before going live.

3.3 Colour scheme

  • Segment rows: dark colours (Segment 1 #34495E, Segment 2 #6C3483).
  • Remove tasks: red → yellow. Install tasks: green → blue.
  • The same task uses the same colour in both segments, so they are easy to compare.

4. Import the custom widget

  1. Go to Stories → Custom Widgets and click Create.
  2. Upload UI5GanttChart.json.
  3. Click Select File and upload UI5GanttChart.zip.
  4. Save. The widget is now available under Insert → Custom Widgets in stories.

5. Create the model

Import the Excel file into a new model and set the column types:

ColumnModel type
OrderDimension (unique ID)
Name, DescriptionDimension
StartDateTime, EndDateTimeGeneric dimension kept as text (not a Date dimension, which drops the time part)
ParentIDDimension
ColorDimension
DummyMeasure
The blog's example date format is 2025-01-01 08:00:00.0000000. The format 2026-10-05 08:00:00 worked in this setup; if bars ever fail to appear, try adding .0000000 to the dates.

6. Add the table (Table_Tasks)

  1. Insert a table on the page based on the new model.
  2. Rename it to Table_Tasks.
  3. Put all dimensions in Rows: Order, Name, Description, StartDateTime, EndDateTime, ParentID, Color.
  4. Put Dummy in Columns.
  5. Show dimensions flat: no hierarchy, no totals.
  6. Optionally hide the table once the chart works; the widget still reads its data.

7. Configure the Gantt widget (GanttChart_1)

Insert the widget from Insert → Custom Widgets and keep the name GanttChart_1.

7.1 Dataset parsing (Builder panel)

Widget fieldMapping
Event IDOrder.id
Event NameName.id
Event DescriptionDescription.id
Event Start TimeStartDateTime.id
Event End TimeEndDateTime.id
Parent IDParentID.id
Color of Event BarColor.id

Field names must match the result set exactly, including capitals. If SAC renamed a dimension on import (for example Start_Date_Time), use that name.

7.2 Table columns (left panel)

Use .description for the dates so the left panel shows SAC's formatted value (e.g. Oct 5, 2026 8:00:00), while the bars keep using .id.

[
  {"field": "Name", "label": "Task"},
  {"field": "Description", "label": "Description"},
  {"field": "StartDateTime.description", "label": "Start"},
  {"field": "EndDateTime.description", "label": "End"}
]

7.3 Horizon settings

With the default Dynamic Total Horizon, the chart starts at today and only looks a short time ahead, so future bars can be hidden. Choose one of these:

  • Option A (recommended): Fixed Total Horizon. Start 2026-10-01 00:00:00, End 2026-11-01 00:00:00.
  • Option B: Dynamic Total Horizon with Look Forward 64800 minutes (45 days) and Look Back 1440 (1 day).

In both cases, tick Dynamic Visual Horizon so the view zooms to fit all the bars.

7.4 Other settings

  • Dataset Timezone Offset from UTC: 0 to start with. Change it only if bars are shifted by hours.
  • Apply Same Color for All Bars: leave empty, or it overrides the hex colours.
  • Automatic Text Color: on (white/black chosen per bar).
  • Bars Opacity: above 0; 0.8 is the default.

8. Scripting

8.1 Where scripts live

  • With Advanced Mode on, hover over a widget in the Outline and click the fx icon, or use the widget's ⋯ → Edit Scripts menu.
  • For load-time scripts, the top node in the Outline (story name, Story or Application; Canvas in older analytic applications) has onInitialization. Names vary by SAC release.

8.2 Table_Tasks → onResultChanged

Runs whenever the table's data changes (including filters):

var rs = Table_Tasks.getDataSource().getResultSet();
console.log(rs);   // optional: inspect in browser console (F12)
GanttChart_1.setDataSet(rs);

8.3 Load trigger (working setup: button)

In this implementation, the onInitialization entry could not be located, so a button was used to load the chart. This was confirmed to work.

  1. Insert a Button and name it Btn_Load (label e.g. "Load Gantt").
  2. Click its fx icon and choose onClick.
  3. Paste the same script as in 8.2.
  4. Run the story and click the button.

If onInitialization becomes available later, paste the same script there so the chart loads without a click.

9. Date display format

SAC can display the date as Oct 5, 2026 8:00:00 when the dimension display mode is set to Description. The result set passes both values to the widget:

StartDateTime: { id: "2026-10-05 08:00:00", description: "Oct 5, 2026 8:00:00" }
  • Bars use .id (machine-readable).
  • Left-panel columns use .description (formatted), as in section 7.2.
Check: open the console after loading and expand one row. If description repeats the id value, SAC is not formatting it for the widget. The fallback is to add display columns (StartDateTime_Desc, EndDateTime_Desc) and map them as the dimensions' descriptions (file GanttChart_Sample_table_v2.xlsx).
